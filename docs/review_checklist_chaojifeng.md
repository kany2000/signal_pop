# 信号弹审稿验收清单（chaojifeng news-brief 对齐版）

> 来源：chaojifeng-video-design `news-brief`（资讯呈现）场景合同。
> 适用于每日版与周末版的「用户审稿」checkpoint；审稿通过后才进入配图/TTS/渲染。
> 本清单是**审稿标准**，不替代成片后的 `qa_chaojifeng.py` 实测与 `check_publish_ready.py`。

## 一、逐条新闻审稿（筛选/文案阶段）

news-brief 最低验收四条，逐条新闻对照打勾：

- [ ] **事实可追溯**：每条关键事实（数字、时间、人物、机构）能指回原始信源；说不出源的表述删掉或降级为"据报道"。
- [ ] **数字与图形一致**：口播里念到的数字与配图/字幕/图表展示的数字完全一致，口径相同（不拿同比环比裸数互比）。
- [ ] **未知不伪装成结论**：预测、传闻、"网友认为"不写成事实；尚未官方确认的信息必须带"尚未确认/据报道"。
- [ ] **未确认与争议被说出**：有争议的事件把争议本身说出来；空缺信息明说"暂无"，不用猜测填坑。

配套硬约束（来自场景合同）：

- [ ] 事件时间、版本、原始来源已核实（48h 时效闸门之外的一律不放行）
- [ ] 事实 / 评论 / 推测三层分开：阿信的机制解读是"评论"，小蓝的反问是"互动"，不得混入事实层
- [ ] 旁白文字改动后，TTS 必须重新生成并重新量时（不允许只改稿不改音频）

## 二、整片结构审稿（周末版）

- [ ] TOP15 倒计时顺序与 parsed_news 匹配，无重复、无遗漏
- [ ] 每条新闻有明确"事件 → 依据 → 变化"链路，不是纯标题复读
- [ ] 突发头条（isBreaking）信息完整度高于普通条目：时间、地点、关键数字、反差细节
- [ ] 经济串讲段落：机制解释准确，含"不构成投资建议"提示
- [ ] 结尾 CTA：互动问题具体可回答，不是空泛"聊聊吧"

## 三、不通过处理

| 情况 | 动作 |
|------|------|
| 关键事实无法追溯 | 删条目（宁缺毋滥），补选备选新闻 |
| 数字/图形不一致 | 改文案或改图，二选一对齐 |
| 未经确认的热点 | 降级为"据报道"或直接丢弃 |
| 改了口播稿 | 全部下游（TTS/字幕/排程/plan.json）重跑，禁止沿用旧音频时长 |

## 四、与产线工具的衔接

```
用户审稿（本清单）通过
  → 配图 → TTS → 渲染
  → python tools/qa_chaojifeng.py <制作日>     # 计划结构 + 成片实测
  → python tools/check_publish_ready.py <制作日>  # 发布文件完整性
  → 发布
```

> 校验器只保证结构与实测一致；画面好不好看、听感对不对、观众能不能懂，
> 仍由人工观看试听验收，未做的检查保持"未验证"状态。
